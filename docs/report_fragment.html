Measuring and reducing hallucination in an agentic RAG system

ATLAS answers technical-support questions from 280 product PDFs using a planner, hybrid retriever, analyzer, synthesizer and verifier. This report shows how I tested it, what the tests found, and what changed.

Static page. Everything below is replayed from saved evaluation runs, so nothing here calls a model or uses any API key. The questions are a synthetic, auto-validated test set drawn from the documentation, not real user traffic.

The Verifier erased every citationThe draft answers were cited. The final answers were not, so the audit trail the system promised did not exist. Found by the citation metric, fixed in one prompt.
Confident answers from the wrong evidenceAsked about a third-party operating system, the analyzer accepted the product's own tuning page and the model wrote a plausible answer. A stronger analyzer plus an abstain rule removed these on the test set.
Run-to-run noise is largeThe retrieved chunks differed between repeated runs for 30 to 43 percent of questions, so every comparison uses repeats and confidence intervals.

How it was measured

Golden set82 questions generated from the corpus by GPT-4o, then checked by Claude against the source chunk. 7 of 84 candidates were rejected. 62 are used for tuning and 20 are held back and not yet scored.
GroundednessThe answer is split into atomic claims. Each claim must be supported by the retrieved text.
Citation precision and recallDoes the cited source support the claim next to it, and does each supported claim carry a correct citation.
Citation validityDoes every citation point at a chunk that was actually retrieved. This catches invented sources.
CorrectnessKey facts from a reference answer, checked against the system's answer.
AbstentionUnanswerable questions must be declined. Answerable ones must not be.
StabilityEach question runs more than once. The spread between runs is reported so noise is not mistaken for progress.
CostEvery call is traced per step, including judge calls, so cost and latency are measured, not estimated.

Limits

Thirty questions and two repeats give wide intervals, and only the hallucination result is large enough to stand out. It rests on two distinct unanswerable questions out of six, so treat it as encouraging, not proven. The test set is synthetic, mostly in a "how do I" style, and each question has a single gold chunk, so retrieval recall is probably understated. The held-out questions have not been scored. The stricter analyzer raises pipeline cost per query about tenfold, and a cheaper two-stage design is the next thing to test.

Correctness and recall rose slightly between the two runs, but the ranges overlap heavily, so I do not claim those gains.
